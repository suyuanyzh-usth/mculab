## 二、真实硬件连接

### 2.1 已实现的部分

- **Web Serial 通道**：`navigator.serial.requestPort()` 直连 USB-TTL，
  数据收发、波特率切换（关闭后以新速率重开）、读循环恢复都已处理。
- **STC89 ISP 烧录协议**：按 stcgal 的协议描述完整实现——

  ```
  帧：46 B9 | 6A | LEN_H LEN_L | payload… | CHK | 16
  1. 2400bps 连发 0x7F 握手，收 0x7F 回显
  2. 读状态包（8×频率计数、BSL 版本、选项字节），反推芯片时钟与 6T/12T
  3. 0x8F 探测 → 切高速 → 读应答 → 切回；0x8E 正式切换
  4. 0x80 乒乓自检 ×4
  5. 0x84 擦除（按 512B 扇区）
  6. 逐 128B 写 Flash，MCU 回送校验和逐块比对
  7. 0x8D 选项字节（保持默认，不擅自改时钟）
  ```

### 2.2 所需软硬件

| 类别 | 要求 |
|---|---|
| 浏览器 | **桌面版 Chrome / Edge 89+**（Firefox、Safari、手机浏览器均不支持 Web Serial） |
| 页面来源 | **HTTPS 或 localhost**（`127.0.0.1`）。纯 HTTP 公网地址下 `navigator.serial` 为 `undefined` |
| USB-TTL | CH340G / CP2102 等，**必须是 5V 电平**（3.3V 会导致握手失败） |
| 目标板 | STC89C52RC / STC89C51RC 最小系统板，11.0592 MHz 晶振 |
| 接线 | TXD→P3.0(RXD)、RXD→P3.1(TXD)、GND↔GND 共地 |
| 复位 | RST 10kΩ 上拉 + 0.1µF 到地 |
| EA | **第 31 脚必须接 VCC**，否则不从内部 Flash 执行 |
| 操作 | 先点"烧录"，再给目标板**断电冷启动**（Bootloader 等待窗口约 1 秒） |

### 2.3 为什么"未验证"——这是必须说清的

**开发环境里没有 STC89C52 实物**，无法对真实芯片做一次完整烧录。
协议实现是对着 stcgal 的协议描述逐字段写的，逻辑上自洽，但真实链路上仍有这些
不确定因素，**首次使用务必按下列顺序自检**：

1. 先用 STC-ISP 官方软件烧一次，确认硬件与接线没问题；
2. 再用本平台烧，看 `#hwLog` 里 `→` / `←` 的十六进制帧：
   - 只想看到 `← 46 B9 68 00 …`（状态包）说明握手成功；
   - 若一直只发不收，检查 TX/RX 是否交叉、是否 5V、是否冷启动；
3. 若停在第 3 步（改波特率），把"烧录波特率"降到 57600 或 38400 重试
   （CH340 在长线/劣质线材下跑 115200 容易丢字节）。

### 2.4 备选方案（若 Web Serial 不可用）

- **服务端串口代理**：服务器插 USB-TTL，用 Node 的串口库转发。
  需要额外安装 `serialport`（有原生模块），并保证服务器物理靠近开发板。
  本平台未内置此通道，需要时可按 `SerialAssistant.backend` 接口补一个实现。
- **纯手动**：学生在本地用 STC-ISP 烧录平台导出的 `.hex`，平台只做仿真与验证。
  这条路零成本、零兼容性问题，**推荐作为课堂默认流程**。

## 三、虚拟示波器 / 逻辑分析仪

### 3.1 已实现能力

- 8 个数字通道，可切换 P0/P1/P2/P3 任一口的 8 位；
- 触发：上升沿 / 下降沿 / 高电平 / 低电平 / 数据字（带掩码）；
- 时基 1 µs ~ 10 ms/div，滚轮缩放、拖动平移、一键定位触发点；
- 双光标测量（T1 / Shift+点击 T2），显示 Δt 与等效频率；
- 自动测量频率、周期、占空比、跳变次数；
- 波形来自 CPU 的**引脚跳变事件流**（带机器周期时间戳），不是事后重绘。

### 3.2 局限：这是"逻辑分析仪"，不是"模拟示波器"

只能看到 0/1 电平，看不到上升沿斜率、过冲、纹波、模拟电压幅值。
原因：平台用离散逻辑模型（每脚 0/1 + 时间戳），没有做电路方程求解。

**若确实需要模拟波形**，需要引入 SPICE 级求解：

| 方案 | 工作量 | 说明 |
|---|---|---|
| ngspice 编译为 WASM | 大 | 需 Emscripten 构建，且要把数字引脚映射成 SPICE 电压源、把模拟结果回灌 |
| 自研简化 RC/二极管模型 | 中 | 只能近似 LED 限流、RC 充放电，无法覆盖三极管/运放 |
| 真实示波器 | 小 | 直接用实验室示波器测实际板子（本平台的逻辑分析仪适合"看时序"，示波器适合"看信号质量"） |

教学上，"中断时序、动态扫描刷新率、通信协议"这三类目标**逻辑分析仪就够了**，
这也是当初选择数字通道的原因。

### 3.3 采样精度的取舍

器件状态每 18 个机器周期刷新一次（≈20 µs），但**引脚事件是逐指令记录的**，
所以逻辑分析仪的时间分辨率实际是"指令级"（1–4 个机器周期），
足以测量 1 kHz 级 PWM 和 9600 bps UART（每位 96 个机器周期）。

对更快的信号（如 100 kHz 以上软件翻转），时间戳仍然准确，但器件视觉刷新会跟不上——
这是渲染层的限制，不影响测量。

## 四、协议解码

| 协议 | 实现 | 备注 |
|---|---|---|
| UART | 起始位检测 + 中点采样 + 停止位校验 | 可选自动波特率（用最短脉宽估计）；也可用当前 CPU 的实际波特率 |
| I²C | 起止条件 + 7 位地址 + ACK/NACK + 数据字节 | 需要 SCL/SDA 在同一采集窗口 |
| SPI | 时钟边沿采样 + 位计数 | 需 SCK/MOSI/CS 三通道 |

通道默认映射：UART→P3.1，I²C→P2.0/P2.1，SPI→P1.0/P1.1/P1.2。若学生接线不同，
需在 I²C/SPI 预设电路下使用（或后续增加通道选择 UI）。

## 五、实验报告自动生成

### 5.1 已实现

- 自动采集证据：编译结果与代码尺寸、仿真机器周期、GPIO 跳变次数、接线诊断结论、
  串口输出片段、原理图元件清单与网络数；
- 两种生成通路：
  - **大模型**（教师配置了 OpenAI 兼容接口）：按固定七段式结构撰写，要求引用真实数据、
    不编造、心得留空；
  - **离线模板**（未配置或调用失败）：生成结构完整、含真实数值的 Markdown 草稿；
- 学生可编辑 → 保存草稿 → 提交；教师端可批阅打分，批阅后学生不可再改（HTTP 409）。

### 5.2 局限

- 大模型输出质量取决于所选模型；平台通过提示词约束"不得编造未给出的数据"，
  但无法 100% 保证，教师批阅仍是必要环节；
- 报告不含真实波形图片（当前只写数值结论）。若要嵌图，可把 SVG 波形序列化后
  作为 Markdown 图片嵌入——需要额外做"波形导出 PNG/SVG"并存储，属于后续增强。

## 六、原理图"零交叉"的真实边界

需求原文："连线之间的引脚要严格准确，不能出现线与线交叉且不能移动"。

已做到：
- 引脚严格按 40 脚 DIP 物理编号；
- 正交布线，枚举 L/Z 共 2+2N 条候选，按交叉数排序，**优先零交叉**；
- 元件不可重叠（放置与拖动都检查）；
- 导线是独立实体，元件移动时端点重新绑定，不会错位；
- 无法零交叉时**明确报告**（导线标橙 + 诊断警告 + 状态栏提示）。

做不到的部分（如实说明）：
- 8 路 LED 从 MCU 的 1 格间距引脚扇出到 3 格高的器件，**几何上不可能全部零交叉**
  （真实电路里也是靠"总线 + 网络标号"解决）。
- 平台目前**没有网络标号组件**。这是彻底解决该问题的正确方案，但需要改网表：
  让同名 label 自动 union。工作量约 1–2 天，属于明确的后续项。

## 七、真实硬件的在线调试（单步 / 断点 / 读寄存器）

**未实现，且用 STC89C52 无法实现。** 原因：

- STC89 系列**没有 JTAG/SWD**，只有串口 ISP（只能整片擦写，不能读回、不能停在断点）；
- 芯片没有硬件断点单元，也没有调试监控程序（monitor）。

若要实现"真机单步 + 看寄存器"，必须换芯片或加监控程序：

| 方案 | 所需硬件 | 所需软件 | 可行性 |
|---|---|---|---|
| 换 STC8/STC15 + SWD 调试器 | STC8A8K64S4A12 开发板 + STC-Link | 厂商调试协议（未公开，需逆向） | 中，工作量大 |
| 加"监控程序"（monitor） | 现有板子即可 | 自己写一段驻留 Flash 的 bootloader，通过串口实现读内存/写内存/单步（用单步中断或重装向量） | 中，需要占用 Flash 与串口 |
| 用仿真器代替 | 无 | 本平台已有（指令级单步 + 全寄存器可见 + 反汇编） | ✅ 现在就能用 |

**教学建议**：真机环节定位为"验证现象"，调试环节放在平台仿真里做——
仿真能看 PC/PSW/SP/RAM 每一个字节，比真机插桩更直观。

## 八、其他已知限制

| 限制 | 影响 | 处理 |
|---|---|---|
| 单文件编译 | 不能做多文件工程、不能链自定义库 | 学生实验都是单文件；需要时把库代码贴在同一个文件里 |
| 编译串行排队 | 50 人同时点编译，最后一位等约 90 s | 见部署指南第四节；或直接用预编译 HEX |
| 仿真速度上限 | 100× 档下单帧最多推进 32 万周期 | 防浏览器卡死，属有意限制 |
| 波形缓存 30 万点 | 超长运行会丢早期波形 | 需要长时观察时用"暂停→采集"分段看 |
| 只支持 8 位端口通道 | 不能同时看 P1 和 P2 | 可切换端口；跨端口时序（如 LCD 的 RS+数据）需分两次采 |
| 无多用户实时协作 | —— | 教学场景不需要 |

## 九、结论

**基础必备功能全部落地并经过自动化验证**（211 项断言 + 浏览器端到端实测）。

**高阶功能中，4 项已实现**（真机串口/ISP、逻辑分析仪、协议解码、串口助手、报告生成），
其中"真机烧录"是协议完整但**缺实物验证**——这是唯一需要你配合确认的一项。

**2 项受物理/芯片能力限制无法在本平台内实现**（真机在线调试、模拟示波器），
原因与替代方案已在 §7、§3.2 写明。
