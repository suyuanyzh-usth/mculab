# 部署指南（局域网 / 校园网 / 公网）

平台是一个**单进程 Node 服务**，不含任何 npm 依赖，数据库为单文件 SQLite。
因此部署只有三件事：准备运行时 → 准备 SDCC → 决定暴露方式。

---

## 零、任意网络能力矩阵（先看这张表）

平台在**应用层**已经把"网络差异"处理掉了，剩下的只是"从哪里暴露出去"。

| 网络场景 | 是否可用 | 依赖 | 说明 |
|---|---|---|---|
| 校园局域网 | ✅ 开箱可用 | 无 | `node server/index.js`，学生用 `http://<IP>:8080` |
| 家庭宽带 / 宿舍（NAT 后） | ✅ 需暴露 | 内网穿透或反代 | 见 §3 方案 B |
| 公网 HTTP | ✅ 仿真/实验全可用 | 公网 IP 或穿透 | ⚠️ 真机烧录会被浏览器禁用（非安全上下文） |
| 公网 HTTPS | ✅ 全功能 | 证书 | 内置 TLS 或 Nginx，见 §2.5 / §3 方案 A |
| 手机 4G/5G | ✅ | 无 | 已做移动端布局，仿真在本地跑，仅首屏耗流量 |
| 弱网 / 高丢包 | ✅ | 无 | gzip 压到 26%、ETag 命中 304（0 字节） |
| 完全断网 | ✅ 可续用 | 先联网访问过一次 | Service Worker 缓存外壳；编译/提交提示需联网 |
| 校园网仅放行 80/443 | ✅ | 反代 | 用 Nginx 转发到 8080，学生访问标准端口 |

**首屏传输量**：未压缩约 810 KB → gzip 后约 **210 KB**；二次访问命中 304，仅数百字节。

## 一、硬件与软件基线

| 项 | 最低 | 建议 |
|---|---|---|
| CPU | 2 核 | 4 核 |
| 内存 | 1 GB | 2 GB |
| 磁盘 | 1 GB（含 277 MB SDCC） | 2 GB |
| Node.js | **22.5+**（必须，`node:sqlite` 从该版本提供） | 22 LTS 最新 |
| 浏览器 | Chrome/Edge 89+（Web Serial 需要） | Chrome/Edge 最新桌面版 |

> `node:sqlite` 是实验性 API，启动时会出现一行 ExperimentalWarning，**不影响功能**。

## 二、局域网部署（最常见）

```bash
# 在服务器/教师机上
cd mculab
node server/index.js --port 8080 --host 0.0.0.0
```

启动横幅会直接打印可用地址：

```
 本机访问     : http://localhost:8080
 局域网访问   : http://10.220.40.181:8080   ← 学生用这个
```

学生用手机/电脑连同一个校园网，直接访问该地址即可。

### 防火墙

Windows 首次运行会弹窗，**必须允许"专用网络"**。若已误点取消，用管理员 PowerShell 补一条规则：

```powershell
New-NetFirewallRule -DisplayName "MCU Lab 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

Linux（ufw）：

```bash
sudo ufw allow 8080/tcp
```

### 开机自启

**Windows**：用「任务计划程序」新建任务 → 触发器「登录时」→ 操作
`node.exe` 参数 `C:\path\to\mculab\server\index.js`，起始于 `C:\path\to\mculab`。

**Linux**：`/etc/systemd/system/mculab.service`

```ini
[Unit]
Description=MCU Lab
After=network.target
[Service]
WorkingDirectory=/opt/mculab
ExecStart=/usr/bin/node server/index.js --port 8080
Restart=always
User=mculab
[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now mculab
```

## 三、公网访问（三选一）

> ⚠️ **重要**：Web Serial（真实硬件烧录）只在 **HTTPS** 或 **localhost** 下可用。
> 纯 HTTP 的公网地址可以正常做仿真与实验，但"连接真实开发板"会被浏览器禁用——
> 平台会在页面顶部显示黄色提示条说明这一点，不会让按钮静默失效。
> 若需要公网也能烧录，用 §方案 0 的内置 TLS 或 §方案 A 的 Nginx 配好 HTTPS 即可。

### 方案 0：内置 HTTPS（不想装 Nginx 时最省事）

平台自带 HTTPS 支持，给一对证书即可直接对外：

```bash
# 自签证书（内网测试/局域网内足够；学生首次访问需点"继续访问"）
mkdir -p certs
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
  -keyout certs/key.pem -out certs/cert.pem \
  -subj "/CN=mculab.local" \
  -addext "subjectAltName=DNS:localhost,IP:192.168.1.10"

node server/index.js --port 443 --tls-cert certs/cert.pem --tls-key certs/key.pem
```

- 也可用环境变量：`MCULAB_TLS_CERT` / `MCULAB_TLS_KEY`
- 有正式证书（学校统一签发 / Let's Encrypt）时把路径换成正式证书即可，浏览器不再告警
- 走 HTTPS 后：会话 Cookie 自动加 `Secure`；**Web Serial 真机烧录功能可用**

> 生产环境仍建议用 Nginx 反代（更好做限流、日志、证书自动续期）。
> 内置 TLS 的价值在于：**没有 Nginx 也能让公网访问用上真机功能**。

### 方案 A：反向代理 + HTTPS（推荐，最稳）

适合：有公网 IP、或有校园网对外映射端口。

1. 平台监听本机即可：`node server/index.js --host 127.0.0.1 --port 8080`
2. 用 Nginx 反代并签发证书（Let's Encrypt 或学校统一证书）：

```nginx
server {
    listen 443 ssl http2;
    server_name mcu.example.edu.cn;

    ssl_certificate     /etc/ssl/fullchain.pem;
    ssl_certificate_key /etc/ssl/privkey.pem;

    client_max_body_size 20m;      # 题库/报告上传

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;   # SDCC 编译最长约 30s
    }
}
server {
    listen 80;
    server_name mcu.example.edu.cn;
    return 301 https://$host$request_uri;
}
```

3. 学生访问 `https://mcu.example.edu.cn`。

> 反向代理不影响登录：会话用的是 `HttpOnly; SameSite=Lax` 的 Cookie，同域下自动携带。

### 方案 B：内网穿透（无公网 IP 时最快）

适合：实验室机器在 NAT 后面，但要让学生宿舍访问。

```bash
# 以 frp 为例（服务端需一台有公网 IP 的机器）
# frpc.ini
[common]
server_addr = <公网服务器IP>
server_port = 7000

[mculab]
type = tcp
local_ip = 127.0.0.1
local_port = 8080
remote_port = 18080
```

学生访问 `http://<公网IP>:18080`。
若穿透服务商提供 HTTPS 域名（如 cpolar / natapp 的 https 通道），优先用 HTTPS 版本。

**注意**：内网穿透的带宽通常只有几 Mbps，100 人同时仿真没问题（仿真全部在浏览器本地跑，
服务端只承担登录、编译、统计），但并发编译会排队（见第六节）。

### 方案 C：云服务器托管

适合：希望 7×24 在线、不依赖实验室机器。

1. 买一台 2 核 2G 的云主机（Ubuntu 22.04）。
2. 上传整个 `mculab` 目录（含 `toolchain/`，约 280 MB）。
3. 安装 Node 22：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

4. **Linux 下需要重新准备 SDCC**（Windows 版 exe 不能直接用）：

```bash
sudo apt install -y sdcc
sdcc --version          # 需 4.x
```

然后让平台指向系统 SDCC（用 `MCULAB_SDCC_BIN` 指定 bin 目录）：

```bash
MCULAB_SDCC_BIN=/usr/bin node server/index.js --host 127.0.0.1 --port 8080
```

> 也可以直接删除 `toolchain/sdcc`，改用系统 SDCC；平台头文件 `platform/include`
> 仍会通过 `-I` 注入，不受影响。

5. 用 Nginx + 证书（同方案 A）对外。

## 四、学生数量与并发

- **仿真**：完全在浏览器本地执行，服务端零负担。100 人同时仿真无压力。
- **登录/提交**：SQLite 单文件，写入是串行的，100 人规模的量级完全够。
- **编译**：每次编译会启动 `sdcc` 子进程，单次约 1.5–2 s。
  服务端已做**串行化排队**（避免 100 个进程同时起来打爆内存）。
  若一个班 50 人同时点编译，最后一位约等 50×1.8s ≈ 90 s —— 会明显卡。
  缓解办法：
  1. 让学生错峰编译（课堂演示时教师统一编译一次）；
  2. 学生可直接加载 `public/hex/*.hex` 里预编译好的产物做仿真；
  3. 服务器加核后，把 `server/compile.js` 的队列改为 2–4 并发（注意内存）。

## 五、数据备份

全部数据在 `data/mculab.db`（含 WAL 文件）。

```bash
# 热备（推荐，SQLite 在线备份）
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/mculab.db');db.exec(\"VACUUM INTO 'backup/mculab-$(date +%F).db'\")"

# 冷备（先停服务）
cp data/mculab.db backup/
```

需要备份的还有：
- `data/sketches/`、`data/reports/`（若使用文件导出）
- `public/hex/`（预编译产物，可重新生成）

**不需要备份**：`data/build/`（编译临时目录，可随时清空）、`toolchain/`（可重新下载）。

## 六、升级平台

```bash
# 1) 备份数据库
# 2) 覆盖代码（保留 data/ 与 toolchain/）
# 3) 重启服务
node server/index.js
```

题库会在启动时以 `server/seed.js` 为准做 UPSERT：
新增的实验会插入，修改过的题目/起始代码会更新，**学生练习记录不受影响**。

若改了 `data/experiments/*.c`，记得重新生成预编译产物：

```bash
node tools/precompile.mjs
```

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 学生打不开页面 | 防火墙未放行；或服务只监听了 127.0.0.1（用 `--host 0.0.0.0`） |
| 编译报"编译进程启动失败" | SDCC 路径不对或不可执行，跑 `bash tools/check_env.sh` |
| 编译报 `error 131: cannot generate code for target 'cs51'` | 端口选项必须写 `-mmcs51`（两个 m），不要写成 `-mcs51` |
| 编译报 `intrins.h: No such file` | 缺少 `platform/include/`，或编译时没带 `-I platform/include` |
| printf 没有任何串口输出 | 用户自己定义了 `putchar` 但签名是 `void putchar(char)`；SDCC 要求 `int putchar(int)` |
| 点击登录没有任何反应，一直停在登录页 | ① 密码错误（现在会在表单下方显示**红色内联提示**，不再只是闪一下的 toast）；② 用「显示密码」核对是否有全角字符/自动填充了旧密码；③ 打开 F12 → Network 看 `POST /api/auth/login` 的状态码 |
| 提示"账号或密码错误"但确定密码没错 | 中文输入法可能打出了**全角**字符（`ｔｅａｃｈｅｒ`）。平台已自动把全角转半角，若仍失败则密码确实不是 `teacher123`，用下面的重置命令 |
| 教师忘记密码 | 在服务器本机执行 `node tools/reset_password.mjs teacher 新密码`（可先 `--list` 查看账号） |
| 名单外的学生却能注册进来 | 早期版本有 3 条绕过路径（不填学号 / 学号空串 / 班级留空），且**保存平台设置会把布尔存成 "true" 导致校验静默关闭**，均已修复。若你的库是旧版本，升级后重启一次会自动迁移历史设置值 |
| 学生注册提示"该学号已激活" | 说明该学号已被本人认领过（已设置密码）。这是防劫持设计：学号不是秘密，不能凭学号重置他人密码 |
| 登录后马上又跳回登录页 | Cookie 被浏览器拦截（第三方 Cookie 限制），确认是同域访问且用 http/https 而非 file://；HTTP 下 `Secure` 不会误加，HTTPS 下会自动加 |
| 真实硬件连不上 | 必须 Chrome/Edge + HTTPS/localhost；USB-TTL 需 **5V 电平**，TX↔P3.0、RX↔P3.1、共地 |
| STC 烧录握手失败 | 必须"先点烧录，再给目标板断电冷启动"；EA(31脚) 接 VCC |

## 八、账号与密码运维

平台不依赖邮件服务（内网部署没有），因此账号找回走本地命令：

```bash
node tools/reset_password.mjs --list              # 列出全部账号
node tools/reset_password.mjs teacher 新密码       # 重置教师密码
node tools/reset_password.mjs 2026001 123456      # 重置学生密码
node tools/reset_password.mjs 2026001 123456 --must-change   # 并强制下次登录改密
```

学生密码也可以由教师在「教师后台 → 学情看板 → 改密」里逐一重置，不必登录服务器。

**登录失败的判断顺序**（排障时按这个走）：

1. 看表单下方有没有红色内联提示——有，说明服务端已返回明确原因；
2. 勾选「显示密码」核对实际输入（全角字符、大小写、自动填充）；
3. F12 → Network：`/api/auth/login` 返回 401 = 凭据错误；返回 5xx = 服务端异常（看控制台）；
4. 完全没有该请求 = 前端脚本没跑起来（检查浏览器控制台报错、或 Service Worker 是否缓存了旧版本：Ctrl+Shift+R 强制刷新）。

## 九、名单准入的规则（教师必读）

平台有两种准入模式，由「教师后台 → 平台设置」两个开关组合决定：

| 允许自助注册 | 名单匹配 | 效果 |
|---|---|---|
| ✅ | ✅ | **推荐**。只有名单内「学号 + 班级」都能对上的学生能注册；学号、班级均为必填 |
| ✅ | ❌ | 自由注册，任何人可注册（学号可留空）。适合公开课、试听、跨专业选修 |
| ❌ | — | 注册入口关闭，学生只能用教师下发的账号密码登录 |

**注册与"认领"的区别**（重要）：

- 教师导入学生时，系统按"学号 = 账号名"预建了账号（初始密码见导入设置）。
- 学生第一次来「注册」，实际上是**认领**这个预建账号：设置自己的密码。
- 认领**只允许发生一次**。因为学号本身就是登录名、不是秘密，
  如果允许反复认领，任何知道同学学号的人都能重置对方密码。
- 认领过（或改过密码）之后再点注册，会提示"该学号已激活，请直接登录"。
  忘记密码只能由教师重置 —— 这是有意的设计，不是 bug。

**一个学号只能对应一个账号**：导入、认领、注册三条路径都会校验学号唯一性，
避免教师看学情时同一个学生的数据被拆到两个账号上。
