## 一、核心技术难点识别

本平台共识别出 **4 个技术难点**，它们决定了整体架构：

| # | 难点 | 影响范围 | 结论 |
|---|------|---------|------|
| 1 | 浏览器内 C → .hex 编译 | 学生 IDE、烧录、仿真全链路 | 必须走服务端 SDCC |
| 2 | 8051 内核指令级仿真（含定时器/中断/UART） | 所有实验项目 | 自研 JS 内核 |
| 3 | 原理图 + 精确引脚 + 网表提取 | 硬件连线、诊断、驱动 | 自研 Canvas 编辑器 + 网表引擎 |
| 4 | 真实硬件连接 | 高阶功能 | Web Serial API + STC ISP 协议 |

## 二、难点 1：C 语言 → .hex 的编译链（已验证可行）

### 2.1 关键结论

**在浏览器里从零实现 C 编译器不可行，必须使用服务端工具链。**

原因：
- 纯 JS 的 8051 C 编译器当代不存在成熟实现（现存方案均为玩具级子集）。
- SDCC（Small Device C Compiler）是唯一成熟、活跃、MIT/GPL 许可的 8051 C 编译器，
  支持 `<stdio.h>`、`<string.h>` 等标准库（`--model-small` + 库函数齐全）。
- SDCC 有 `mcs51` 后端，天然输出 Intel HEX。

### 2.2 实际下载与解压验证（本机实测）

```
源: https://downloads.sourceforge.net/project/sdcc/sdcc-win64/4.6.0/sdcc-4.6.0-x64-setup.exe
大小: 9,949,266 字节
类型: NSIS-3 Unicode 安装包（可用 7-Zip 无损解压，无需管理员权限安装）
解压: 7z x -o<dir> sdcc-setup.exe  →  3909 个文件 / 279 MB
```

解压后关键二进制（`toolchain/sdcc/bin/`）：

| 程序 | 作用 |
|------|------|
| `sdcc.exe` | 编译器驱动（前端） |
| `sdcpp.exe` | 预处理器 |
| `sdas8051.exe` | 8051 汇编器 |
| `sdld.exe` | 8051 链接器 |
| `makebin.exe` | .ihx → 二进制 |
| `packihx.exe` | 规范化 Intel HEX（去除冗余记录） |
| `ucsim_51.exe` | **指令级 8051 模拟器（可作黄金参照/oracle）** |

### 2.3 编译命令（实测通过）

```bash
sdcc -mmcs51 --model-small --iram-size 128 --code-size 8192 --stack-auto -o out.ihx main.c
packihx out.ihx > out.hex
```

实测输出（LED 流水灯）：
```
:0300000002004EAD
:100008000000E2FBEAF2802C0000E0FBEAF080242A
...
:00000001FF
```
→ **Intel HEX 生成正确，EOF 记录规范。**

### 2.4 决策

- 编译走 **Node 服务端调用 SDCC**，返回 `.hex` 文本 + `.rst`/`.lst` 供调试。
- 同时把 `ucsim_51.exe` 保留为**仿真内核的交叉验证 oracle**（多脚本校验用）。
- 若学校服务器不具备 SDCC（如纯云托管），提供 **`__ASM__` 内联汇编回退通道** +
  **纯 JS 8051 汇编器**，保证平台在没有 SDCC 时仍可完成全部实验。

## 三、难点 2：8051 内核仿真

### 3.1 调研结论

现成方案：
- `Aimini/js51`（GitHub）：JS 8051 模拟器，SFR 可扩展，但**无中断源/定时器**，需自行补齐，教学不完整。
- `S2Sofficial/8051sim`：浏览器 8051 模拟器，README 明确「无外设、无定时器、无中断、无 7 段数码管支持」→ 不满足需求。
- `CrispStrobe/emu8051-stc`：MIT，含 STC12/15/89 外设模型 + WASM 构建，质量高。
  但为 emu8051 fork，外设模型针对 STC 增强型，接口（SFR 监听）较为复杂，
  且其 WASM 需从源码构建（Emscripten 工具链，本机无）。

### 3.2 决策：自研 JS 内核

理由：
1. 教学平台需要**可解释性**：每条指令的机器周期、SFR 变化要能可视化（单步/断点/反汇编）。
2. 需要**与外设模型深度耦合**：P0–P3 引脚变化要直接驱动 LED/数码管/LCD/蜂鸣器，
   且要能被示波器以精确时间戳采样。
3. 自研可保证 **12T 机器周期模型精确**（12 时钟/机器周期，11.0592 MHz 晶振），
   这对数码管动态扫描刷新率、UART 波特率、PWM 波形教学至关重要。
4. 零依赖 → 校园内网离线可用。

自研范围（必须实现）：
- 255 个操作码（111 条指令 / 7 种寻址方式）
- PSW 全标志位（CY AC F0 RS1 RS0 OV P）动态更新
- 128B IRAM + 可扩展 XRAM + 8KB Code（STC89C52 为 8KB Flash / 512B RAM）
- Timer0 / Timer1（模式 0/1/2/3，GATE、C/T、溢出中断）
- 外部中断 INT0/INT1（电平/边沿触发）
- UART（模式 0/1/2/3，SM2、多机通信、波特率含 Timer1 与 SMOD）
- 位寻址区 20H–2FH + 可位寻址 SFR

### 3.3 交叉验证方案

用 SDCC 自带 `ucsim_51.exe` 作为 oracle：同一 .hex 在两个内核上跑，比对
IRAM/XRAM/SFR/P1 输出序列。这是"多脚本模拟测试"的核心手段。

## 四、难点 3：原理图与网表

### 4.1 需求拆解

「连线之间的引脚要严格准确，不能出现线与线交叉且不能移动的情况」解读为：
1. **引脚必须严格对应真实封装**（40-pin DIP 的物理引脚号 ↔ 逻辑端口名 P1.0…）。
2. **导线不允许"视觉交叉"**——即两条导线不得以十字交叉且无节点的方式重叠
   （那在真实原理图中代表"不连接"，但视觉上会误导学生）。解决办法：
   **正交布线 + 自动绕行（jog）**，交叉时自动插入 Z 形折弯；同一电平面走不同"轨道"。
3. **不能移动**——导线一经绘制应稳定，元件移动时导线随之重算而不错位。

### 4.2 STC89C52 引脚表（40-pin DIP，实物核对）

| Pin | 名称 | Pin | 名称 |
|-----|------|-----|------|
| 1–8 | P1.0–P1.7 | 40 | VCC |
| 9 | RST | 39–32 | P0.0–P0.7（**右侧自下而上**）|
| 10 | P3.0/RXD | 31 | EA/VPP |
| 11 | P3.1/TXD | 30 | ALE/PROG |
| 12 | P3.2/INT0 | 29 | PSEN |
| 13 | P3.3/INT1 | 28–21 | P2.7–P2.0 |
| 14 | P3.4/T0 | 20 | GND |
| 15 | P3.5/T1 | 19 | XTAL1 |
| 16 | P3.6/WR | 18 | XTAL2 |
| 17 | P3.7/RD | | |

> 注意：P0 与 P2 在 DIP 上为**倒序**排布，这是学生最易出错之处，必须是平台诊断规则之一。

### 4.3 网表模型

采用 **Net = 一组 (组件, 引脚) 的等价类**，用并查集（Union-Find）求解。
每个 Net 内含 `drivers`（推挽输出脚）与 `readers`（输入脚）。
MCU 端口写入 → 触发 Net 电平重算 → 传播到器件 → 器件状态更新 → 重新渲染。

## 五、难点 4：真实硬件连接

### 5.1 通道选型

| 方案 | 可行性 | 结论 |
|------|-------|------|
| Web Serial API | Chrome/Edge 89+ 桌面版支持，需 HTTPS 或 localhost | ✅ 采用 |
| WebUSB | 需驱动/权限，普通 USB-TTL 芯片（CH340）无 WebUSB 固件 | ❌ |
| 服务端串口代理（Node serialport） | 可绕过浏览器限制，但需服务器插板 | ✅ 作为备选 |

**决策**：主用 Web Serial（浏览器直连、零安装），服务端串口代理作为备选。

### 5.2 STC89 ISP 协议（完整逆向自 stcgal，已存档）

来源：`stcgal/protocols.py`（本目录 `stcgal_protocols.py`）

**帧格式（主机 → MCU）：**
```
46 B9 | 6A | LEN_H LEN_L | payload... | CHECKSUM(1B) | 16
START   HOST   长度=payload+5   ...       sum(packet[2:])   END
```
- `PACKET_START = 0x46 0xB9`
- `PACKET_HOST  = 0x6A`（主机发）／`PACKET_MCU = 0x68`（MCU 发）
- `PACKET_END   = 0x16`
- 校验：`sum(从长度字节起的所有字节) & 0xFF`

**握手流程：**
1. 以 `baud_handshake`（2400，自适应）连续发送 `0x7F`，MCU 冷启动后回显 `0x7F`。
2. MCU 回**状态包**：`payload[0]==0x00`，含 8 组频率计数（big-endian uint16）、
   BSL 版本（`[17]`高位.低位, `[18]`ASCII step）、选项字节 `[19]`。
3. `mcu_clock_hz = (baud_handshake * freq_avg * cpu_T) / 7.0`，
   其中 `cpu_T = 6.0`（6T 模式）或 `12.0`（12T，`options & 1 == 0`）。
4. **切换波特率**（命令 `0x8F` 探测 → `0x8E` 正式）：
   ```
   BRT = 65536 - round(fosc / (baud_transfer * sample_rate))
   sample_rate = 32 (12T) / 16 (6T)
   包体 = 8F | BRT_H BRT_L | (0xFF - BRT_H) | brt_csum | delay(0xA0) | iap_wait
   brt_csum = (2 * (256 - BRT)) & 0xFF
   iap_wait: <5MHz→0x83, <10MHz→0x82, <20MHz→0x81, else 0x80
   0x8E 包体少 iap_wait 字节
   ```
5. **Ping-pong 测试**：`80 00 00 36 01 | mcu_magic_H mcu_magic_L`，连续 4 次回 `0x80`。
6. **擦除**（命令 `0x84`）：`84 | blocks | 33×6`，其中
   `blocks = ceil(erase_size/512) * 2`。返回 `0x80`。
7. **写 Flash**（命令 `0x00` 头 3 字节 + 地址 + 长度 128）：
   ```
   packet  = 00 00 00 | addr_H addr_L | 00 80 | data[128]
   packet += 0x00 填充至 135 字节
   csum    = sum(packet[7:]) & 0xFF
   MCU 返回 payload = [0x80, csum]  ← 校验和比对即逐块验证
   ```
   `PROGRAM_BLOCKSIZE = 128`（受芯片 RAM 限制）
8. **选项字节**（命令 `0x8D`）：`8D | msr | FF FF FF`，返回 `0x8D`。

> 该协议在浏览器端可用 Web Serial 完整实现，因为只需 `write` / `read` 与 `setSignals`，
> 不需要特殊 ioctl。**这是本平台"真实硬件"功能可行的关键依据。**

### 5.3 硬件清单（真实连接部分）

- 1× USB-TTL 模块（CH340G/CP2102，**必须是 5V 电平**）
- 1× STC89C52RC 最小系统板（11.0592 MHz 晶振，RST 10k 上拉 + 0.1µF 到地）
- 杜邦线：TXD↔P3.0(RXD)、RXD↔P3.1(TXD)、GND↔GND
- ⚠️ 冷启动：点击"下载"后必须断电重上电（Bootloader 等待窗口约 1 秒）
- ⚠️ EA(31 脚) 必须接 VCC 才能从内部 Flash 执行

## 六、总体架构决策汇总

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | 原生 ES Module + 自研组件 | 零构建、内网离线可用 |
| 编辑器 | CodeMirror 5.65.18（本地内置） | 无构建步骤，体积小 |
| 后端 | Node.js 原生 `node:http` | 零 npm 依赖，规避内网 npm 不可用 |
| 数据库 | `node:sqlite`（Node 22 内置） | 无需编译原生模块，单文件持久化 |
| 编译 | SDCC 4.6.0（本地可移植解压） | 唯一成熟的 8051 C 工具链 |
| 仿真 | 自研 JS 8051 内核 | 可解释性 + 外设耦合 + 零依赖 |
| 大模型 | OpenAI 兼容 HTTP 代理 | 兼容任意厂商，密钥只存服务端 |
| 公网 | 反向代理 / 内网穿透 / 云托管 | 见部署指南 |

   - 需 secure context；`navigator.serial.requestPort()` 须用户手势触发

   - Aimini/js51、S2Sofficial/8051sim、CrispStrobe/emu8051-stc
