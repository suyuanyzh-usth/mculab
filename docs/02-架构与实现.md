# 架构与实现说明

本文说明平台的技术选型、模块划分、关键算法与验证方法。目标是让后续接手的人
（或半年后的你自己）能在半小时内看懂"为什么这么写"。

---

## 一、技术选型与理由

| 层 | 选择 | 放弃的方案及原因 |
|---|---|---|
| 前端 | 原生 ES Module + 自研组件 | 不用 React/Vue：内网可能无法装 npm 包，且需要"双击即可用"的离线能力 |
| 编辑器 | CodeMirror 5.65.18（本地内置） | Monaco 体积大、需打包；CM5 单文件即可用 |
| 样式 | 手写 CSS（一套变量 + 8 个视图栅格） | 不用 Tailwind/Bootstrap：避免构建链 |
| 后端 | Node 内置 `node:http` | 不用 Express：零依赖是硬要求（校园网 npm 常不可用） |
| 数据库 | `node:sqlite`（Node 22 内置） | 不用 better-sqlite3：需要原生编译，学生机上装不了 |
| 编译 | SDCC 4.6.0 便携版 | 不用 Keil：商业授权、无法服务端调用；不用自研 C 编译器：不可能覆盖标准库 |
| 仿真 | 自研 JS 8051 内核 | 见下节 |
| 大模型 | OpenAI 兼容 HTTP 代理 | 不直连各家 SDK：一套接口兼容 DeepSeek/通义/Ollama |

### 为什么自研 8051 内核

调研过的现成方案（详见 `docs/research/00-调研总览.md`）：

- `Aimini/js51`：只有核心 SFR，**没有中断源和定时器**，无法做定时器/中断/串口实验。
- `S2Sofficial/8051sim`：README 明确"无外设、无定时器、无中断、无 7 段数码管"。
- `CrispStrobe/emu8051-stc`：质量高（MIT），但需要 Emscripten 自行构建 WASM，且其 SFR
  监听接口与外设模型是围绕 STC 增强型设计的，耦合成本高。

教学平台需要三件现成方案给不了的东西：

1. **可解释性**——每条指令的机器周期、PSW 标志、寄存器变化要能单步观察；
2. **外设时序精度**——数码管刷新率、UART 波特率、PWM 占空比必须算得准；
3. **引脚级联动的可控性**——端口电平变化要能带时间戳喂给逻辑分析仪。

所以自研，并用 **SDCC 自带的 `ucsim_51` 作为黄金参照**做交叉验证（见第五节）。

## 三、8051 内核（`public/js/core/cpu8051.js`）

### 3.1 时序模型

12T 模式：1 机器周期 = 12 振荡周期；11.0592 MHz 晶振 → **921.6 kHz 机器周期**（1 周期 ≈ 1.085 µs）。

`step()` 的职责是"取指—计周期—执行"，其中：

```js
const c = CYCLE[op] || 1;   // 该操作码的机器周期数
this.tick(c);               // 先推进定时器/串口/cycles
const used = this.exec(op); // 再执行语义
```

> ⚠️ 这是一个容易踩的坑：`step()` **内部已经调用 `tick()`**。
> 外部再写 `cpu.step(); cpu.tick(c)` 会把时间记账翻倍。
> 早期标定软件延时时就因此把 1 ms 算成了 2 ms，导致所有延时短一半。

### 3.2 准双向口模型

```js
pinValue(port) = portLatch[port] & portExt[port]
```

`portExt` 是"外部拉低掩码"：器件把某脚拉低就把对应位清 0。
这正确复现了"写 1 才能读回外部低电平"的经典 51 行为，也是按键/矩阵键盘能工作的前提。

### 3.3 中断

- 5 个源：INT0 / T0 / INT1 / T1 / 串口，向量 0x03 / 0x0B / 0x13 / 0x1B / 0x23。
- 优先级：IP 位决定两级；同级按自然优先级。响应时压栈 PC 并清 TF/IE（串口 RI/TI 不清）。
- `intLevelActive` 记录当前服务级别，`RETI` 时清除，用于实现"同级不嵌套、高级可打断"。

### 3.4 UART

- 4 种模式；模式 1/3 的波特率 = `(2^SMOD/32) × (fosc/12)/(256−TH1)`。
- 发送：把字节展开成"起始位+8 数据+停止位"，按 `bitCycles()` 逐位驱动 P3.1，
  因此逻辑分析仪看到的是**真实 UART 波形**，不是事后画出来的。
- 接收：`feedSerial()` 注入字节同样展开成波形驱动 P3.0，置 RI。

### 3.5 本机发现的真实缺陷（已修）

| 缺陷 | 症状 | 根因 |
|---|---|---|
| TCON 掩码 | 定时器永不启动 | 可写位是 bit0/2/4/6，掩码应为 `0x55`，早期写成 `0x0F` 把 TR0/TR1 挡掉了 |
| RET 字节序 | 子程序返回跳到错误地址 | 8051 压栈先 PCL 后 PCH，`SP` 先自增再存；弹栈要先弹 PCH |
| `softReset` | 复位后程序被擦光 | `reset()` 会 `code.fill(0)`，必须先复制副本 |
| `runCycles` | 外设不前进 | `step()` 已含 `tick()`，外部不能再调 |

## 四、原理图与网表（`schematic.js` + `circuit.js`）

### 4.1 引脚定义的真实性

`MCU_DIP40_PINS` 按 40 脚 DIP 封装逐个定义（含物理脚号）。特别注意：

- 左侧 1–8 是 P1.0–P1.7，9=RST，10–17 是 P3.0–P3.7，18/19=XTAL2/XTAL1，20=GND；
- 右侧自上而下是 40=VCC、39–32=P0.0–P0.7（**倒序**）、31=EA、30=ALE、29=PSEN、28–21=P2.7–P2.0。

P0/P2 倒序是学生最容易接错的点，也是诊断规则之一。

### 4.2 正交布线 + 零交叉优先

`routePath(a, b)` 枚举三类候选路径：

1. 两个 L 形（先横后竖 / 先竖后横）；
2. 多个 Z 形（中段在若干"轨道偏移"上：0,±1,±2,…,±8）。

对每条候选计算"与既有导线的交叉数"，选最小者。零交叉不可达时：
仍然生成导线，但把 `crossings` 记在导线对象上（渲染成橙色），并在状态栏提示
"建议移动元件或改用其它引脚"。

> **已知局限**：8 路 LED 与 MCU 的 P1 引脚之间是"1 格间距 → 3 格高度器件"的扇出，
> 物理上无法全部零交叉（真实电路里也是靠总线/网络标号解决）。
> 预设电路因此会出现若干交叉警告，这是**如实报告**而不是隐藏。
> 后续若要做真正的零交叉，需要引入"网络标号（net label）"组件，让同名网络自动连通。

### 4.3 网表

并查集（Union-Find）：每条导线把两端引脚 union 到同一集合，最终每个集合是一个电气网络。
网络记录 `hasVcc / hasGnd / low / high`，供器件求值。

### 4.4 电平穿透（这一条很关键）

```js
netLevel(net) {
  if (net.hasGnd) return 0;
  if (有 CPU 引脚) return cpu.readPin(pinId);
  if (net.hasVcc) return 1;
  // 否则沿电阻/电感/排阻穿透（深度 ≤ 4）
  ...
}
```

真实电路里 `P1.0 ——1kΩ—— 三极管基极` 是蜂鸣器实验的标准接法。
如果只看直连，基极网络既没 CPU 引脚也没电源/地，会被判成"悬空=高"，
三极管恒导通、蜂鸣器不响。加入穿透后，这类"经限流电阻驱动"的电路才正确。

### 4.5 边沿敏感器件

LCD1602 的 E 选通脉冲只有 1–2 个机器周期宽，而器件刷新是每 18 个机器周期一次，
**必然漏采样**（表现为 DDRAM 永远是空的）。

解决：`CircuitSim` 挂到 `cpu.onPinChange`，对 LCD/74HC595 做到"引脚一变就响应"，
同时保留周期刷新处理电平型器件（LED、数码管）。这是性能与正确性的折中。

## 五、验证方法（这是本平台最值得看的部分）

### 5.1 与 ucsim_51 逐字节对拍

`tests/oracle.test.mjs` 的做法：

1. 用 SDCC 编译 6 个覆盖不同特性的 C 程序（算术/位操作/定时器中断/串口/栈/长整型）；
2. 用 **SDCC 自带的 ucsim_51** 跑 3000 条指令后 dump 状态；
3. 用本平台内核跑同样 3000 条指令；
4. 比对 PC / ACC / B / PSW / SP / DPTR / R0–R7 / 指令数 / 振荡周期数。

结果：**5 个用例逐字节一致，1 个（定时器中断）差 1 个机器周期**——
中断采样相位差，属于可接受范围（已在测试中显式标注为"相位容许内"）。

> 工具链调用为什么放在 bash 脚本里？因为本仓库的开发环境禁止 Node 派生子进程，
> 所以 `tools/make_oracle_fixtures.sh` 负责生成 fixture，测试只读 fixture。
> 在正常部署环境里，服务端是可以正常 spawn SDCC 的。

### 5.2 实验行为验证（不只是"能跑"）

`tests/experiments.test.mjs` 对 15 个实验逐个：**预设原理图 → 装载预编译 HEX → 跑 N 个机器周期 → 检查可观测现象**。

例如：
- 流水灯：必须出现 8 种"单点低"图案，且任一时刻恰好 1 只 LED 亮；
- 数码管动态扫描：瞬时只有 0–1 位被驱动（证明是扫描而不是全亮）；
- 矩阵键盘：注入按键后扫描读数出现新组合，松开后恢复；
- LCD1602：DDRAM 里出现可打印字符串；
- UART：注入 `0x41` 后 TXD 上真的出现了回显字节；
- PWM：按窗口统计占空比，必须同时出现 <35% 和 >65% 且连续变化。

### 5.3 软件延时标定

`tools/calibrate_delay.mjs` 用真实编译+执行测出"1 ms 对应多少机器周期"，
反推循环常数。当前：内层 28 次 ≈ 916 周期 ≈ 1 ms（误差 0.6%），
实测流水灯每步 **198.8 ms**（目标 200 ms）。

这类"用仿真器反过来标定示例代码"的做法，是本平台自洽性的一种体现——
如果内核时序错了，延时也对不上。

## 六、编译服务（`server/compile.js`）

流水线：

```
源码 → Keil 语法翻译 → printf 注入 → SDCC 编译 → packihx → .hex
                ↓                                   ↓
          错误解析（行号）                     失败则回退内置汇编器
```

### 6.1 Keil C51 兼容翻译

国内教材几乎都是 Keil 写法，学生复制粘贴后直接喂 SDCC 会一片 syntax error。
平台做保守替换：

| Keil | SDCC |
|---|---|
| `sbit LED = P1^3;` | `__sbit __at (0x93) LED;`（位地址 = SFR 字节地址 + 位号） |
| `unsigned char code tab[]` | `__code unsigned char tab[]` |
| `void isr() interrupt 1` | `void isr() __interrupt(1)` |
| `bit flag;` | `__bit flag;` |
| `xdata / idata` | `__xdata / __idata` |

> 位地址公式踩过坑：`sbit` 的地址是 `SFR地址 + 位号`（如 P2=0xA0 → P2^5=0xA5），
> **不是** `SFR×8 + 位号`（那是 0x20–0x2F 内部 RAM 位区的算法）。
> 写成后者会得到 0x505，超出位寻址范围，汇编器报 `Page 0 Address Error`。

### 6.2 printf 注入的两个坑

1. **不能先等 TI**：复位后 `TI=0`，`while(!TI);` 会死等。必须先直接写 SBUF，之后才等。
2. **必须插在 `#include <stdio.h>` 之后**：若插在文件最前面，SDCC 不会把 `putchar`
   生成为 `.globl` 符号，链接 `vprintf` 时报 `Undefined Global _putchar`，程序跳飞。

### 6.3 降级通路

SDCC 不可用时，可用 `__ASM__` 开头写汇编，走平台自带的 8051 汇编器（纯 JS，零依赖）。
另外 15 个实验都已预编译到 `public/hex/`，学生即使完全没有 SDCC 也能直接加载仿真。

## 七、前端视图层

8 个视图，每个 `js/ui/view-*.js` 只导出 `init() / show()`：

| 视图 | 关键点 |
|---|---|
| problems | Markdown 渲染题面；一键"载入起始代码 + 对应电路" |
| ide | CodeMirror；编译错误可点击跳到行；Ctrl+B 编译 |
| circuit | SVG 编辑；点元件库放置 → 连线工具点两个引脚自动布线 |
| sim | 按墙钟时间推进仿真（1× = 实时）；单帧上限 32 万周期防卡死 |
| scope | 波形 SVG 绘制（10 格时基 + 双光标 + 触发标记） |
| report | AI/离线生成草稿 → 学生补心得 → 提交 |
| qa | 提问自动附带代码与诊断结果 |
| teacher | 名单导入、学情看板、AI 分析、大模型设置、批阅 |

`ui/core.js` 提供共享能力（`$`、`api()`、`markdown()`、`toast`、`modal`、`state`、`bus`），
视图之间不互相 import，避免循环依赖。
