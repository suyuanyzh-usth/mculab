# 任意网络 + 免 .bat：三种部署方式

目标：**学生打开一个网址就能用，你不需要每天开电脑、也不需要点任何 .bat**。

---

## 先看对比，再选一条

| | 方案 A：云服务器 + Docker | 方案 B：云服务器直接跑 | 方案 C：本机常驻服务 | 方案 D：云端链接 |
|---|---|---|---|---|
| 需要你的电脑开着 | ❌ 不需要 | ❌ 不需要 | ✅ 需要 | ❌ 不需要 |
| 任意网络可访问 | ✅ | ✅ | 需公网/穿透 | ✅ |
| **C 语言在线编译** | ✅ | ✅ | ✅ | ✅（已内置 Linux 版 SDCC） |
| 真机烧录（Web Serial） | ✅ 配 HTTPS | ✅ 配 HTTPS | 仅 localhost/HTTPS | ✅ |
| 数据持久化 | ✅ volume | ✅ 目录 | ✅ | ⚠️ 随沙箱重建可能丢 |
| 需要会 Linux | 一点点 | 一点点 | 不需要 | 不需要 |
| 成本 | 云主机 ~30–60 元/月 | 同左 | 0 | 0 |

**结论**：
- 想**立刻能用**、不折腾 → 方案 D（云端链接已上线，编译可用）。
- 要**正式跑一学期** → 方案 A：数据可备份、性能独占、可绑域名 HTTPS。
- 只有一台校内电脑、且必须用它 → 方案 C。

## 方案 A：云服务器 + Docker（推荐）

### 1. 买一台最便宜的 Linux 云主机

2 核 2G 足够（仿真全在学生浏览器里跑，服务器只负责编译/登录/统计）。
系统选 **Ubuntu 22.04 / 24.04**。安全组放行 **80、443**（以及测试用的 8080）。

### 2. 装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
```

> 国内网络若拉取镜像慢，可配置镜像加速器（阿里云/腾讯云控制台有专属地址）。

### 3. 把项目传上去

在**你自己的电脑**上执行（把路径和 IP 换成你的）：

```bash
# 只需传这些，Windows 版工具链不用传（镜像里用 apt 的 SDCC）
tar -czf mculab.tgz \
    --exclude='toolchain' --exclude='data' --exclude='node_modules' \
    --exclude='.git' --exclude='certs' --exclude='.playwright-cli' \
    mculab
scp mculab.tgz root@<服务器IP>:/opt/
```

服务器上解压：

```bash
cd /opt && tar -xzf mculab.tgz && cd mculab
```

### 4. 启动

```bash
# 强烈建议先改掉默认教师密码
export MCULAB_TEACHER_PWD='你的强密码'
docker compose up -d --build
```

第一次构建会 `apt install sdcc`，并在**构建期编译一个真实程序做自检**——
如果镜像里的工具链有问题，构建会直接失败，不会等到学生用时才发现。

验证：

```bash
docker compose ps          # 应为 healthy
curl http://127.0.0.1:8080/api/health
```

浏览器打开 `http://<服务器IP>:8080`，用 `teacher / 你的密码` 登录。

### 5. 配域名 + HTTPS（强烈建议）

HTTPS 不只是"安全一点"：**Web Serial（真机烧录）只在 HTTPS 下可用**。
用 Caddy 两步搞定，证书自动申请自动续期。

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`：

```
mcu.你的域名.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
```

把域名的 A 记录指向服务器 IP 即可。Caddy 会自动申请 Let's Encrypt 证书。

> 没有域名？也可以用 IP + 自签证书：
> `docker run` 时加 `-e MCULAB_TLS_CERT=... -e MCULAB_TLS_KEY=...` 并把 443 映射出来，
> 但学生浏览器会提示"不安全"，不适合正式课堂。**建议花 30 元买个域名**。

### 6. 以后改代码怎么上线

```bash
cd /opt/mculab
# 覆盖改动的文件（server/ public/ 等）
docker compose up -d --build
```

数据在 Docker 命名卷 `mculab-data` 里（容器以非 root 运行，命名卷会自动继承正确属主，
不会出现"SQLite 只读"）。重建镜像不会丢学生账号与练习记录。

备份这个卷：

```bash
docker run --rm -v mculab-data:/d -v "$PWD":/b alpine tar czf /b/mculab-data.tgz -C /d .
# 恢复：docker run --rm -v mculab-data:/d -v "$PWD":/b alpine sh -c "tar xzf /b/mculab-data.tgz -C /d"
```

## 方案 B：不用 Docker，直接跑在 Linux 上

适合：不想装 Docker，或者用学校的 Linux 服务器。

```bash
# 1) Node 22
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# 2) SDCC（关键：Linux 版由发行版提供）
sudo apt install -y sdcc
sdcc --version        # 确认 4.x
which packihx

# 3) 平台
sudo useradd -r -s /bin/false mculab || true
sudo mkdir -p /opt/mculab && sudo chown -R mculab:mculab /opt/mculab
# 上传项目到 /opt/mculab（同上，可不传 toolchain）

# 4) 注册为系统服务（开机自启，不需要任何 .bat）
sudo cp deploy/mculab.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mculab
systemctl status mculab
```

平台会自动在 PATH 里找到 `sdcc`，不需要额外配置。
若 SDCC 装在非标准位置，编辑 service 文件里的 `MCULAB_SDCC_BIN`。

日志：`journalctl -u mculab -f`

## 方案 C：Windows 本机常驻（不用点 .bat，但仍依赖这台电脑）

适合：只有一台校内电脑可用，且它能拿到公网 IP 或被映射出去。

```powershell
# 以管理员身份运行 PowerShell（只需做一次）
powershell -ExecutionPolicy Bypass -File deploy\install-windows-service.ps1
# 换端口：加 -Port 8090
# 卸载： 加 -Uninstall
```

脚本会：
1. 用 `node server\index.js` 注册为 **Windows 服务**（开机自启、崩溃自动重启由系统托管）；
2. 自动放行防火墙（仅专用/域网络）；
3. 打印访问地址。

之后**再也不需要点任何 .bat**。改完代码执行 `Restart-Service MCULab` 即可生效。

> ⚠️ 局限：电脑关机/断网/休眠时学生就用不了；校园网通常也不给公网 IP。
> 要"任意网络"，仍需方案 A/B，或用内网穿透（frp/cpolar），但穿透又回到"本机必须开着"。

## 方案 D：直接发布成云端链接（已上线，无需服务器）

这是最省事的方式：**不用买服务器、不用装 Docker、不用开电脑**，学生打开链接就能用。

### 当前线上地址

```
https://mcu-lab-00765.app.workbuddy.host/?sharecode=66BKSCXL7J
```

- 教师账号 `teacher`，初始密码见交付说明（**请登录后立即修改**）
- 数据（学生账号、练习记录）存在云端数据库，与你的电脑无关
- 你的电脑关机、这个任务关闭，学生照常使用

### 云端也能编译 C（关键）

发布沙箱里原本没有 SDCC，且不能 `apt install`。解决办法是把 **Linux 版 SDCC 随项目一起上传**：

```
toolchain/sdcc-linux/
├── bin/{sdcc,sdcpp,sdas8051,sdld,packihx,makebin}   ← 来自 Debian 官方包
└── share/sdcc/{include,lib/small,lib/small-stack-auto}
```

平台按可执行文件位置推导数据目录，所以这套布局可以脱离 `/usr/share` 独立运行。
另外修了两个 **Debian 4.2.0 包自身的头文件错误**（`stc89.h` 里 `0xNNNH` 后缀、
`RCAP2L` 重复声明四次、`WDT_CONTR` 地址写错），已与官方 4.6.0 头文件对齐。

实测：云端 `sdcc --version` 正常，编译流水灯产出 245 字节合法 HEX，耗时 22ms。

### 怎么更新线上版本

改动代码后：

```bash
node tools/make_cloud_bundle.mjs     # 重新生成 cloud/（约 10MB，含 Linux 工具链）
# 然后用发布能力重新发布 cloud/ 目录，链接不变
```

`cloud/` 只是发布用的瘦身副本：不含 280MB 的 Windows 工具链、不含学生数据、不含测试。
**不要在 cloud/ 里改代码**——它每次都会被重新生成。

### 局限（必须知道）

| 项 | 情况 |
|---|---|
| 数据持久性 | 沙箱可能随发布重建，学生数据不保证长期保留。**正式教学请用方案 A/B** |
| 性能 | 共享沙箱，多人同时编译会排队 |
| 备份 | 无法直接访问数据库文件；需要长期保存请走方案 A/B |
| 域名 | 平台分配的二级域名，不可自定义 |

**结论**：云端链接适合"立刻能用、先跑起来"、评审演示、小班试用；
一个学期的正式课程建议方案 A（Docker + 自己的服务器 + 域名 + HTTPS）。

## 编译能力是怎么保证的（工程细节）

平台对工具链的定位顺序（`server/compile.js`）：

1. 环境变量 `MCULAB_SDCC_BIN` 指定的目录
2. 项目内 `toolchain/sdcc/bin`（Windows 便携版；Linux 也可解压官方压缩包到此）
3. 系统 `PATH` 里的 `sdcc`（**Docker 镜像与 apt 安装都是这条**）

`Dockerfile` 在构建期会真的编译一次示例程序并校验 HEX 的 EOF 记录，
所以"镜像里编译不可用"这种问题不会拖到部署之后才暴露。

启动横幅会直接告诉你工具链状态：

```
 SDCC 工具链  : 可用 SDCC : ... 4.x
```

若显示"未找到"，检查 `sdcc --version` 与 `MCULAB_SDCC_BIN`。

## 常见问题

| 现象 | 处理 |
|---|---|
| 容器起来了但页面 502 | `docker compose logs -f` 看是否端口被占用；确认 `PORT` 一致 |
| 编译报"未找到可用的 SDCC" | 镜像里没装上：`docker exec -it mculab which sdcc`；或自己 `apt install sdcc` |
| 字体/中文乱码 | 镜像已带 UTF-8；自建机若为精简系统，`apt install fonts-noto-cjk` 只影响服务端截图，不影响浏览器 |
| 学生数据在重建镜像后丢了 | 没挂载 volume：检查 `docker-compose.yml` 是否还有 `mculab-data:/app/data` |
| 报 `SQLITE_CANTOPEN` / 数据库只读 | 用了宿主机目录做挂载但属主不对：`sudo chown -R 1000:1000 ./data`，或者改回命名卷 |
| 想换端口 | 改 `docker-compose.yml` 的 `"8080:8080"` 前一个数字，容器内仍 8080 |
| 公告/站点名改不了 | 教师后台 → 平台设置；注意**保存后要刷新页面** |

## 附：发布后如何确认"线上真的是最新版"

新增了核查工具，一条命令给出结论：

```bash
node tools/verify_deploy.mjs "https://<域名>/?sharecode=<分享码>" <教师密码>
```

它会依次检查：站点可达 → 分享码网关 → 教师登录 → **六项新能力是否已上线** → 云端编译器。

判定规则：接口返回 **404 就是旧版本**（路由不存在）；403/401 说明被网关或权限挡住，
此时工具会标"无法判断"，而不是假装通过。
